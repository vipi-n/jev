01 / Start here
JEV / noun

An AI decision engine for software.

Jev is TypeSafe AI’s first “System One” model. Its job is narrow: read the current state of a program, judge a set of bounded questions, and return typed answers with uncertainty.

It does not compose an email, invent a plan, or hold a conversation. Your code still owns the workflow. Jev supplies the fuzzy judgment in the middle—where normal if statements are too brittle.

Jev vs. JSON mode

JSON mode asks a generative LLM to produce text that matches a schema. Jev’s output space is typed before inference and its answers are produced as decisions, not generated as a string and parsed afterward. Type-safe output prevents malformed shapes; it does not guarantee the judgment itself is correct.

05 / For software engineers

Anatomy of
a Jev-shaped call.

This is conceptual pseudocode, designed to show the contract rather than copy a specific SDK version.

decision.tsconceptual
const result = await jev.decide({
  state: {
    message: ticket.body,
    plan: account.plan,
    recentCharges: ledger.last90Days
  },

  questions: {
    topic: choice([
      "billing", "technical", "account"
    ]),
    severity: score({ min: 1, max: 3 }),
    needsHuman: noul()
  }
});

if (result.needsHuman.probability > 0.85) {
  routeToHuman(ticket);
}
1

State is evidence, not a prompt persona

Provide the facts needed for the judgment. More context is useful only when it is relevant and trustworthy.

2

Questions define the legal output space

The model cannot invent a fourth topic when the only choices are billing, technical, and account.

3

Probabilities become policy inputs

Your code chooses thresholds based on the cost of a false positive, false negative, and human review.

4

Actions stay outside the model

Jev recommends a typed decision. Your application authorizes and executes the real-world action.

06 / Confidence is part of the product

What should happen at 88%?

A probability is not a promise. It is a signal your system can combine with the cost of being wrong. A well-calibrated model saying “88%” should be correct roughly 88 times across many similar cases—not necessarily on this one case.

Calibration ≠ accuracyAccuracy asks “how often is it right?” Calibration asks “does its confidence honestly match how often it is right?”

08 / Under the hood, at a high level

Why TypeSafe calls it
“System One.”

The name comes from the idea of fast, intuitive judgment. Jev is optimized for many small decisions rather than long, sequential language generation.

A

Different training target

Chat models are commonly tuned to produce responses people prefer. TypeSafe says Jev uses Reinforcement Learning for Calibrated Decisions—RLCD—to train for useful decisions whose confidence reflects uncertainty.

B

Parallel, not token-by-token

An LLM generates a string one token after another. TypeSafe says Jev evaluates the declared questions and their possible outcomes in parallel, which is central to its latency and cost profile.

C

Less freedom on purpose

Jev gives up arbitrary string generation. That restriction is the feature: the model stays inside the answer space your program declared, making the result easier to compose and validate.

About the big benchmark numbers

TypeSafe reports up to roughly 194× faster and 445× cheaper on its published workflow evaluations. The company also says those gains are likely at the high end, and the evaluations use its own workflow harness and reference methodology. Treat them as vendor results—not universal guarantees—and run private evaluations on your own cases.

Why “Jev”?

TypeSafe says the name refers to economist William Stanley Jevons and the Jevons paradox: when a resource becomes dramatically more efficient, total demand can rise. Their bet is that much cheaper machine judgment will create many more places to use it.

10 / The honest version

Type-safe is not
truth-safe.

Jev narrows one class of failure. It does not make judgment, data, or workflow design infallible.

01

It can be wrong

A valid answer can still be the wrong answer. “Billing” is a legal choice even if the message was actually about account access.

02

Inputs shape outcomes

Missing, stale, biased, or adversarial state can produce a bad judgment with a perfectly valid type.

03

Question design is engineering

Vague questions, overlapping choices, and poor scales create unreliable workflows. Evaluation is still required.

04

Vendor numbers need context

Speed, cost, and accuracy claims depend on workload and methodology. Test Jev on your own data and failure costs.

“Zero hallucinations” needs a precise reading.

TypeSafe uses the phrase for guaranteed schema matching: Jev cannot emit an output outside the declared type. That does not mean zero semantic mistakes. A type-valid decision can still be incorrect.

11 / Quick answers

Still wondering
what it is?

These are the distinctions that usually make the idea click.

Is Jev an LLM?

TypeSafe presents Jev as a new “System One” model rather than a smaller chat LLM. Public material describes a different architecture, parallel sampling, and a training method called Reinforcement Learning for Calibrated Decisions. Its observable distinction is simpler: it returns typed probabilistic decisions instead of generated strings.

Does Jev replace ChatGPT or Claude?

No. Use a generative LLM when you need language, code, planning, or open-ended reasoning. Use Jev when software needs a bounded judgment. A workflow may use Jev to decide what should happen and an LLM to write the final message.

Why not use normal if-statements?

Keep exact facts in code. Jev is for conditions that are hard to enumerate, such as whether a message sounds like a cancellation threat or whether evidence supports a fraud concern.

Why not use a traditional classifier?

A classifier can be excellent for one stable task, but usually needs task-specific labeled data and retraining. Jev is positioned as a more general decision model that receives the question and output type at call time.

Who decides the final action?

Your application. Jev returns judgments and uncertainty. Code applies permissions, thresholds, business rules, logging, and human-review policies before an action occurs.
